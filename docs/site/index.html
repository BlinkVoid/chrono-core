What is Chrono Core?

Chrono Core is a local-first project memory tool that captures what happened in your work sessions and makes it queryable later. It records structured handoffs — summaries, files changed, tests run, decisions, blockers, next actions, risks, and git state — into a canonical local SQLite store.

Any AI coding agent can call it through the Model Context Protocol (MCP), and humans can use the same features from the chrono CLI. Everything stays on your machine: no cloud, no accounts, no telemetry.

Why?

Project state gets scattered across TODO files, plans, chat sessions, issue notes, and half-updated docs. After a project pauses for weeks, simple questions become hard: what happened last? What is blocked? Which decisions still matter? Which docs are stale or contradictory?

Chrono Core treats continuity as an explicit artifact: captured at handoff time, distilled over time, and surfaced exactly when you or your agent resume — scoped to the branch you are actually on.

Features

Session handoff capture
chrono handoff records summary, changed files, tests, decisions, blockers, next actions, risks, and git state via flags or a JSON payload.
Branch-scoped resume
chrono resume shows only the current workstream's open items; --all, --branch, and --limit widen or trim the view.
Full lifecycle verbs
Complete, cancel, edit, reopen, or supersede actions and blockers so corrections replace stale state instead of duplicating it.
Cross-project bug tracking
chrono bug report/list/show/update tracks bugs across every project in the workspace, exposed via MCP tools too.
Full-text search
chrono search runs SQLite FTS5 queries over captured observations.
Markdown export
Derived project wiki pages and a top-level ReviewQueue.md for human review.
Deterministic review heuristics
Doc reconciliation, stale-doc detection, health scoring, and improvement advice — deterministic heuristics, not semantic/AI reconciliation.
MCP server
chrono-mcp exposes 20 tools backed by the same store and code paths as the CLI.

How it works

      |
      v

      |
      v
Chrono Core service layer
      +-- Project resolver / workspace traversal
      +-- Session capture
      +-- Management distillation
      +-- Documentation reconciliation
      +-- Resume-context generator
      |
      v
Store (canonical local state)
      +-- SQLite tables (WAL mode)
      +-- FTS indexes
      +-- graph-shaped edge table
      |
      v
Derived views
      +-- project wiki markdown
      +-- ReviewQueue.md

The database is canonical; markdown exports are readable views on top of it.

Quick start

Requires Python ≥ 3.12. PyPI publication is pending — install from a checkout today:

# once published:
uv tool install chrono-core

# today, from a clone of this repository:
uv pip install -e .

Capture a session handoff from inside any project:

chrono handoff \
  --summary "Implemented JWT token refresh; tests green." \
  --file src/auth/tokens.py \
  --test "pytest tests/test_tokens.py" \
  --decision "Use short-lived access tokens with rotating refresh tokens" \
  --blocker "Staging Redis credentials not provisioned yet" \
  --next "Wire refresh endpoint into the client SDK"

Later — even weeks afterwards — get back up to speed:

$ chrono resume

Project: demo-app
Status: Latest session on spike/queue-backend.
Latest session: Spiked Redis Streams vs SQS; leaning Redis Streams.

Open blockers (spike/queue-backend):
Next actions (spike/queue-backend):
  - [act_dbd199039c1c49a1] Write spike findings into docs/queue-spike.md
  (+1 more on other branches: --all to show)

FAQ

Is it AI-based?
No. Distillation and review run on deterministic heuristics — predictable, inspectable, and reproducible.
Does it need the cloud?
No. Everything lives in a local SQLite database (WAL mode with FTS5 indexes). No network access required.
Which agents does it work with?
Anything that speaks MCP. The chrono-mcp server exposes 20 tools; humans get identical functionality via the CLI.

Not yet published — local preview artifact.
